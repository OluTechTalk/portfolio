## LinkedIn

I built my portfolio the way I build products: five episodes, each with a written plan.

Most portfolios are a page of logos. I wanted mine to show both halves of the job: how I frame a problem as a PM, and proof that I build the thing myself.

So I scoped it like a product:
→ Episode 1: a coming-soon page live on the domain
→ 2: design system and hero
→ 3: project cards
→ 4: a build log, one post per episode, checked at build time
→ 5: a case study, About page, and polish

What broke:
→ My first push said "repository not found." The repo existed; my laptop's credentials just couldn't see it.
→ My first color refresh read as "LinkedIn blue" in the preview screenshots. It never shipped.
→ Lighthouse on my laptop swung from 57 to 87 on the same page. The culprit was leftover local servers. Measure where the measurement is reliable.

The PM lesson: ship the smallest public version, then let real feedback steer.
The builder lesson: don't trust a number until you trust how it was measured.

Every number on the site links to its source.
